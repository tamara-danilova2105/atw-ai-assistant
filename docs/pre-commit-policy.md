# Pre-Commit Policy — ATW AI Assistant

## 1. Назначение

Pre-commit — локальный quality gate.

Цель:

- не допускать lint-ошибки
- не допускать type errors
- стандартизировать качество кода
- снизить нагрузку на review

---

# 2. Текущие проверки

| Этап   | Инструмент | Назначение |
|--------|------------|------------|
| commit | ruff format | автоформатирование |
| commit | ruff check  | линтинг |
| push   | pyright     | проверка типов |

Файл конфигурации: `.pre-commit-config.yaml`  
Расположение: корень проекта.

---

# 3. Установка

```bash
poetry add --group dev pre-commit
poetry run pre-commit install
poetry run pre-commit install --hook-type pre-push
```

---

# 4. Поведение

- `git commit` → запускается ruff
- `git push` → запускается pyright
- при ошибках операция отменяется

---

# 5. Расширение проверок (Future Roadmap)

Pre-commit будет усиливаться по мере роста проекта.

Планируемые направления:

## 5.1 Тесты

Добавление запуска pytest на этапе push:

```
poetry run pytest
```

Push невозможен при падающих тестах.

---

## 5.2 Безопасность

Планируется подключение:

- detect-secrets — предотвращение утечки токенов
- bandit — базовый security-анализ

---

## 5.3 Архитектурные проверки

Возможное добавление:

- запрета межслойных импортов
- проверки структуры проекта
- запрета использования print()
- запрета прямого обращения к инфраструктуре из API слоя

---

## 5.4 Усиление типизации

По мере стабилизации проекта:

- переход pyright в strict режим
- запрет неаннотированных публичных функций
- минимизация использования Any

---

# 6. Принудительный пропуск (не рекомендуется)

```
git commit --no-verify
git push --no-verify
```

Используется только в исключительных случаях.

---

# 7. Архитектурная позиция

Pre-commit — локальный уровень защиты.  
CI (при наличии) — уровень репозитория.  
Protected branches — организационный уровень.

Процесс должен обеспечивать невозможность попадания невалидного кода в основную ветку.
